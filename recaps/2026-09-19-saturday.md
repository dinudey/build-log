**Loose ends**
**Ethics and Trust — AI UX Ethics Analyzer** (started 2026-04-19, status: active but dormant)

The experiment set out to answer two questions: can Claude analyze visual and prototype artifacts — wireframes, Figma exports, HTML prototypes — and produce ethics assessments that are actionable for *UX designers* rather than researchers or engineers? And can the output meaningfully sort findings into three buckets: what a designer directly controls, what requires cross-functional collaboration, and what is outside design scope entirely?

What was built: dashboard wireframe concepts exploring what the ethics-analyzer interface itself might look like, generated in Claude Code Design. The output was a 71KB HTML file with multiple layout options for surfacing assessments against the five parameters (Trust, Explainability, Transparency, Fairness, Accountability).

What never happened: the actual analysis pass. The wireframes sketch a UI for the output, but the experiment never ran Claude against a real artifact to see if the output was any good. This is the open loop.

**Artifact potential**
**High.** The ethics and trust experiment has real case study potential — not as a "here's a tool I built" post, but as a design-research question explored with AI. The framing "can an AI assess an AI product's UX for ethical compliance, and can it distinguish what designers own from what they don't?" is genuinely novel. The designer/org accountability split in particular hasn't been written about clearly in the design community. Worth finishing the experiment first (run the analysis, evaluate the output quality), then writing up what worked, what was useless, and what the output revealed about the limits of AI as an ethics reviewer.

### This week's nudge

Three specific experiments worth running in the next 1–2 hours each:

**1. Complete the ethics audit loop (Ethics and Trust, round 2)**
Take one of the wireframes already built in `ethics and trust/wireframes.html` and write a Claude Code prompt that runs it through the five ethics parameters in READ.md. The goal isn't a polished tool — it's to get one real output and ask: is this useful to a UX designer, or does it read like a compliance checklist? If the output sounds like researcher-speak, that's the finding. This closes the open loop and directly tests the original hypothesis in under an hour.

**2. Claude Code as a design-review slash command**
Write a `/review-design` slash command that accepts a screenshot path or URL and outputs a structured critique across three lenses: (1) what communicates clearly without explanation, (2) what requires trust from the user but isn't earning it, (3) what's missing that an AI-aware user would expect. Sixty-minute build that tests whether code-adjacent tooling can bring design critique into a development workflow — not to replace judgment, but to surface it faster and consistently.

**3. AI disclosure pattern library**
Build a minimal, self-contained HTML file (no framework needed) showing five common AI disclosure patterns: confidence indicators, explanation toggles, data provenance labels, human-review flags, and opt-out affordances. Each pattern gets a one-sentence annotation: when it earns trust vs. when it erodes it. This feeds directly back into the ethics analyzer experiment as reference material, and stands on its own as a shareable artifact for the design community.
