### Ethics & Trust Analyzer
`experiments/ethics and trust/`

**What it was trying to learn**
Whether Claude can analyze visual and prototype artifacts — user flows, Figma screens, HTML prototypes — and produce ethics assessments that are genuinely actionable for UX designers, not just legible to researchers or policy teams. The secondary question was whether the output could meaningfully separate what a designer can change unilaterally, what requires cross-functional work, and what is outside design's scope entirely.

**What was actually built**
A 71KB single-file interactive HTML prototype: the Ethics & Trust Analyzer dashboard. It explores four distinct interaction directions, each with three screens (Overview, Deep-dive on a finding, Scope of Influence appendix):

- **01 · Report Document** — Linear, printable format structured like a formal assessment. Designed for handoff gates and PM/Eng sharing as a PDF-equivalent.
- **02 · Dashboard Grid** — KPI-first layout with pillar score cards and a prioritized findings list. Aimed at designers who need to track an artifact across multiple review cycles.
- **03 · Canvas Annotate** — Visual annotation interface that overlays findings directly onto a prototype frame context.
- **04 · Split Inspector** — Navigation + table + side panel pattern, optimized for scanning many findings quickly.

The prototype runs against a sample artifact (a checkout flow, 14 screens parsed) and scores across 10 ethics pillars: Fairness (71), Accountability (48), Transparency (55), Explainability (42), Trust calibration (66), Privacy (74), Consent (58), Bias & inclusivity (63), Error handling (51), Dark patterns (80).

**Non-obvious decisions and tradeoffs**

*Scope-of-influence as a first-class output.* Every finding is tagged with one of three scopes: YOU OWN THIS / WORK W/ OTHERS / ESCALATE/FLAG. This is the experiment's core design bet — that the missing piece in ethics tooling isn't more findings but clearer agency. Existing frameworks tell designers what is wrong; they don't address who can actually fix it. Making scope a visual tag on every card changes the conversation from "here's what's unethical" to "here's what you're accountable for."

*Socratic rather than prescriptive tone.* Each finding includes a guiding question (e.g., "What signal would help a user decide whether to accept this?") alongside a suggested fix. The prototype treats Claude's role as opening inquiry rather than handing down verdicts — which matters for adoption, since designers often resist tools that feel like external auditors rather than thinking partners.

*Four directions instead of one.* The experiment deliberately avoided converging on a single design. Generating four structurally different UI patterns is itself a method — it makes the interaction assumptions visible and testable, rather than baking one model in early.

*Tweaks panel for live customization.* A small but telling choice: the prototype includes controls for paper tone (warm/cool/plain), accent color, and a "sketch wobble" slider that adjusts the hand-drawn aesthetic. This signals a hypothesis that tool personality affects how seriously ethics output is taken — a warm, slightly rough aesthetic might land differently in a design critique than a clinical dashboard.

**What it unlocked or proved**
- Ethics analysis can be structured for designer agency rather than researcher review. The three-tier scope model creates vocabulary that didn't previously exist for cross-functional ethics conversations.
- The four-direction format validated that there isn't one obvious right answer — the "correct" interaction model likely depends on team structure (lone designer vs. embedded in Agile) and artifact stage (early exploration vs. pre-launch gate).
- HTML as a medium for design exploration proved fast: one session produced four complete layout explorations with real sample data, real scoring, and interactive navigation — faster than a comparable Figma exploration would take.

**Loose ends**
- No real artifacts have been run through the tool yet — the data is hardcoded sample output. The next step would be testing whether the format holds when Claude actually generates the analysis, not just renders pre-written findings.
- The scope model hasn't been validated with a real designer. The YOU/COLLAB/OUT taxonomy might need more nuance (e.g., "you can prototype this, but it needs Legal review before shipping").
- Status is still "active" — no clear stopping point defined.

**Artifact potential**
**Flag: HIGH.** The scope-of-influence framing is genuinely new. Most AI ethics tooling is built for researchers, auditors, or executives — not for the designer who is actually making the interaction decisions. A case study titled something like *"Who can fix this? Designing AI ethics output for UX practitioners"* would be shareable with the broader product design community. The four-direction exploration method is also worth documenting separately as a Claude Code design workflow.

### This week's nudge

No new commits landed in the week of May 9–16. Three experiments worth trying in the next session:

**1. Test whether the Ethics Analyzer output format is actually machine-producible.**
Pick one of the four dashboard directions and write a Claude prompt that generates a real ethics assessment in that exact format — structured markdown with scope tags, pillar scores, and Socratic questions. Run it against an actual screen description or Figma export. The wireframe assumed the output would be coherent; test whether it actually is.

**2. Apply the scope-of-influence model to a different domain.**
The YOU / WORK W/ OTHERS / ESCALATE/FLAG taxonomy was built for ethics, but the underlying problem — outputs that don't address who can act on them — exists everywhere. Try mapping an accessibility audit, a content moderation review, or a copywriting feedback session through the same three-tier structure. Does the model generalize, or is it ethics-specific?

**3. Document the Claude Code design session protocol.**
The experiments repo is accumulating artifacts without a documented method.
