**What I worked on**

### Experiment: AI UX Ethics Analyzer (`ethics and trust/`)

The core question: can Claude function as an actionable ethics reviewer for UX designers — not a compliance checklist, not an engineering audit, but something a designer can run against their own artifacts (Figma exports, HTML prototypes, user flows) and walk away with specific things to change?

The experiment carries two linked hypotheses. First, that Claude can evaluate visual artifacts against five AI UX ethics parameters — Trust, Explainability, Transparency, Fairness, and Accountability — with enough specificity to be useful at the design level. Second, that the output needs an explicit scope layer: which findings can a designer address solo, which require cross-functional collaboration, and which are outside design's influence entirely. Without that layer, ethics feedback tends to either overwhelm with systemic problems no individual can touch, or shrink to cosmetic fixes that don't move the needle.

What was built: a full wireframe prototype — via Claude Code Design — of what the analyzer would look like as a product surface. The output is a 71KB HTML dashboard with a warm paper aesthetic (handwritten Caveat headers, IBM Plex Mono for analytical data, amber accents on a paper-white ground) and a three-color scope system: moss green for designer-owned issues, ochre for cross-functional, clay red for out-of-scope. Multiple layout options were generated within a single session.

---

**Key decisions or tradeoffs**

The scope-coloring system is the non-obvious bet. Most ethics tooling presents findings as a flat list, which quietly places the burden of triage on the designer. Building the scope distinction directly into the visual output — before the question of how to analyze is even settled — means the prototype is already encoding an opinion about what *actionable* means in this domain. That's a design argument, not just a UI choice.

Using Claude Code Design to prototype the analyzer (rather than sketching by hand or in Figma) creates a useful feedback loop: the tool being designed is itself AI-generated, which means `wireframes.html` now exists as a Claude-readable artifact that could be fed back into the experiment as input for the next phase.

---

**What it unlocked**

Proof that Claude Code Design can generate credible, opinionated UX artifacts — not generic wireframes, but something with a distinct visual language and embedded product logic. Also establishes the wireframes as a reusable prompt artifact: a Claude-generated prototype of a Claude-powered tool, ready to serve as input for phase two.
