**What I worked on**

**AI UX Ethics Analyzer** (`ethics and trust/`)

The core question this experiment was chasing: can Claude analyze a UI artifact — a prototype, a set of screens, a Figma export — and give feedback that's actually useful to a UX designer, rather than a researcher or engineer? The dominant failure mode of AI ethics tooling is that it surfaces principles without grounding them in what a designer can actually change. This experiment tried to solve that.

The output is a 71KB HTML prototype exploring 4 distinct interface directions, each rendered across 3 screens (overview, deep-dive, scope appendix). The 4 directions: Report Document, Dashboard Grid, Canvas Annotate, and Split Inspector. Built in Claude Code.

---

**Key decisions or tradeoffs**

The central structural insight — and the non-obvious one — is the three-scope model:
- **In your scope** — what the designer can change directly
- **Collaborate** — what requires cross-functional coordination (PM, engineering, legal)
- **Out of scope** — systemic or organizational constraints beyond design's reach

Without this distinction, ethics feedback tends to either overwhelm designers with things they can't touch or underdeliver by only surfacing surface-level issues. The color system (moss green / ochre / clay) bakes the model into the visual language rather than leaving it to the copy.

Second non-obvious choice: Socratic prompts interspersed with findings, rather than a pure fix list. "If a user lost trust after using this flow once, which screen would you suspect first?" is a different epistemic mode than "Add rationale to your AI suggestion card." One invites reflection; the other prescribes. The prototype uses both, but their relative weight is still an open design question.

The hand-drawn aesthetic (Caveat + IBM Plex Mono) signals "thinking tool" rather than polished product — an intentional positioning that keeps the prototype from looking more finished than it is.

The 4-direction exploration produced a clear v1 candidate: the Report Document direction feels most natural for the primary use case. The prototype is ready to wire up to a real Claude API call — the UX shell is there; the AI integration is the remaining unknown.

## This week's nudge

No new commits across experiments in the past ~2.5 months. Three concrete things worth trying this weekend:

**1. Wire up the ethics analyzer**
Take `wireframes.html` as the reference UI and write a single Claude prompt that reviews a real 5-screen onboarding flow against the five ethics pillars, outputting structured JSON with scope tags (you / collab / out). The prototype assumed Claude could do this; test whether it actually can. ~90 minutes. The interesting failure modes are as valuable as success — if Claude collapses the scope categories or misses the designer/engineer distinction, that's the next design problem to solve.

**2. Claude Code design decision log**
Create a session-end hook in `.claude/settings.json` that appends a single-line entry to a local `design-log.md` every time a session closes: the session date, a one-line summary of what changed, and any rejected alternatives noted in the transcript. After a week of normal use, you'd have a searchable record of every AI-assisted design decision you made. Implementation is one hook + one append script; the value is in the artifact it produces over time.

**3. Scope model as a general-purpose prompt**
Strip the ethics framing entirely and test whether the three-scope model (you / collab / out) holds up as a generic lens for any product decision. Pick a real current design problem, write a prompt that asks Claude to categorize every concern or constraint using those three buckets, and see if the output is more actionable than a standard "pros and cons" framing. This costs nothing to try and if it works it becomes a reusable thinking tool, not just an ethics artifact.
