### Experiment: AI UX Ethics Analyzer

**What it was trying to learn**

The central question: can Claude analyze visual UX artifacts — flows, screens, HTML prototypes — and return ethics feedback that is actually useful to a UX designer, not just to researchers or policy teams? The framework used was five AI UX ethics parameters: Trust, Explainability, Transparency, Fairness, and Accountability.

The harder secondary question: can the output meaningfully distinguish between what a designer can fix directly, what requires cross-functional negotiation (engineering, product, legal), and what is entirely outside design's scope? This distinction matters because most existing AI ethics frameworks hand designers moral responsibility without structural power to act on it.

**What was actually built**

A set of wireframe explorations for a dashboard concept, generated in Claude Code Design and committed as a 71KB HTML artifact. This wasn't a prompt-and-review loop — the wireframes appear to be the output of an iterative co-design session, exploring what an ethics analysis dashboard might actually look like as a UI. The artifact is a concrete deliverable: shareable, iterable, and stakeholder-presentable.

**Non-obvious decisions and tradeoffs**

The choice to use Claude Code Design as the prototyping environment — rather than Figma or a code-first approach — is itself meaningful. Building an AI ethics analysis tool inside an AI-native design tool creates a productive feedback loop: the process becomes evidence for the question being asked. The experiment is partly about what was built and partly about what it felt like to build it this way.

The README deliberately left the scope open, noting "wireframes with options" as the result rather than a defined screen. This was likely the right call for an exploratory pass — converging too early would have foreclosed the more interesting design territory.

**What it unlocked**

Proof that a meaningful AI UX ethics review workflow can be sketched end-to-end in a single session: define the parameters, generate dashboard concepts, assess the output. The work also implicitly scoped the hardest unsolved problem: the designer-control taxonomy (what belongs to design vs. engineering vs. policy) is not a UI challenge — it's an information architecture and governance challenge that needs resolution before any dashboard can be genuinely actionable.

**Loose ends**

- No ethics analysis pass was run against a real product artifact — the analyzer was designed but not validated against actual input
- The designer-control taxonomy was identified as critical but never built out
- No feedback from practicing UX designers on whether the wireframe output reads as actionable

---

**Artifact potential**

**High.** Strong candidate for a written case study: *"What it looks like to build an AI ethics reviewer for UX practice — inside an AI-native tool."* The angle is both the artifact (a real wireframe dashboard) and the meta-layer (using Claude Code Design to design an AI design tool). The tension between designer agency and systemic responsibility is sharp and publishable. Target audience: UX practitioners curious about AI-native design workflows and ethics in design practice.

## This week's nudge

No new activity since April 2026. Here are three specific experiments worth trying in the next 1–2 hours:

**1. Run the ethics analyzer on a real product you actually use.**
Pick any app you interact with daily — a banking app, a notification system, a recommendation feed. Screenshot the key flows. Feed them to Claude with the five parameters from the ethics and trust experiment (Trust, Explainability, Transparency, Fairness, Accountability). Ask for a structured assessment: what can be seen from the UI alone, what can't be assessed without knowing the underlying model, and what the designer could change vs. what requires policy. This validates the core question of the experiment with zero build time and produces a concrete analysis artifact.

**2. Build a Claude Code routine that maintains the build-log itself.**
Design a short Claude Code session — as a CLAUDE.md prompt sequence or scheduled task — that scans dinudey/experiments weekly, flags any folder with no commits in 30+ days, and drafts a brief status note per experiment (active, stalled, or dormant). This is infrastructure for the system itself and a concrete example of AI-native maintenance workflow. The deliverable is a working routine, not a writeup.

**3. Prototype the missing "designer-control layer" as a card artifact.**
The ethics analyzer experiment identified the designer-control taxonomy as the hardest unsolved piece: which ethics concerns are design-owned, which are cross-functional, and which are out of scope entirely. Build it as a simple card UI in Claude Code Design — one card per parameter (Trust, Explainability, etc.), each with three columns. The deliverable is a printable reference artifact a design team could actually use, not a working app. This closes the biggest open question from the April experiment without requiring any new infrastructure.
