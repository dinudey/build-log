**What I worked on**

**Experiment: AI UX Ethics Analyzer** (`ethics and trust/`)

The core question was whether Claude can review a visual design artifact — a Figma export, an HTML prototype, a PDF of screens — and produce ethics feedback that is actually useful to a UX designer. Not useful to a researcher or an engineer. Useful to the person who owns the interaction layer but not the system architecture.

The secondary question was more specific: can the output distinguish between what a designer can change unilaterally, what requires cross-functional coordination, and what is simply out of design's scope and needs to be escalated? Most ethics tooling ignores this distinction entirely and leaves designers holding findings they have no power to act on.

What was built is a dense, self-contained HTML wireframe prototype — 1,400+ lines, 71KB — exploring four different layout directions for an Ethics & Trust Assessment dashboard. It's a working artifact, not a sketch. The prototype includes real sample data: a fictional checkout flow (v3, 14 screens) scored across 10 ethics pillars — Fairness (71), Accountability (48), Transparency (55), Explainability (42), Trust calibration (66), Privacy (74), Consent (58), Bias & inclusivity (63), Error handling (51), Dark patterns (80). Five specific findings are fleshed out in full, each tagged with a scope-of-influence label.

The four layout directions explored:
- **01 · Report Document** — linear, printable, narrative-first
- **02 · Dashboard Grid** — scannable overview, pillar cards
- **03 · Canvas Annotate** — findings mapped spatially to screens
- **04 · Split Inspector** — side-by-side finding detail and scope breakdown

---

**Key decisions or tradeoffs**

The most consequential design decision in the whole prototype is the scope-of-influence taxonomy. Every finding is tagged as one of three things:

- **YOU OWN THIS** — the designer can act directly
- **WORK W/ OTHERS** — requires eng, legal, content, or product alignment
- **ESCALATE / FLAG** — outside design's jurisdiction; needs to be surfaced upward

This reframes the tool from an audit instrument to a triage instrument. The implicit argument is that dumping 40 ethics findings on a designer with no indication of who can actually fix them produces learned helplessness, not action. The scope tags route energy toward what's moveable.

The second notable decision: each finding includes a **Socratic prompt** (the "ask" field) alongside the fix recommendation. The ask is a question, not an answer — *"What signal would help a user decide whether to accept this?"* This keeps designers in an agentive, reasoning mode rather than passively implementing recommendations. It's a deliberate choice against the pattern of AI tools that do the thinking for you.

The prototype is titled V3, which implies earlier versions were tested and discarded — the wireframe is the result of iteration, not the starting point.

**What it unlocked**

- A concrete UI pattern for design responsibility triage — the scope-of-influence framework (you / collab / out) is reusable far beyond ethics tooling, applicable to any multi-stakeholder design review
- Proof that a Claude-assisted ethics analysis can be presented at designer literacy — pillar scores, trend lines, actionable copy, specific screen references — without requiring the designer to know anything about ML fairness literature
- A working prototype that could be demoed or extended: the sample data is structured, the layout directions are distinct, and the interactivity (tweaks panel, tab navigation) is functional
- A template for how to structure AI feedback to preserve human agency: scope first, socratic prompt second, fix third

## This week's nudge

Nothing was committed April 26 – May 2. Three experiments worth trying in 1–2 hours:

**1. Claude as design reviewer with an opinion**
Paste a real UI screenshot or Figma frame URL into Claude and ask it to review the design as a senior IC designer — not a list of accessibility issues, but a point of view: what's working, what's fighting the user, and what one change would have the highest leverage. The experiment is about calibrating how much Claude's taste aligns with yours, and where it diverges in interesting ways. Document the delta.

**2. Commit log as a thinking trace**
For one day, write every commit message as if it's a journal entry — not what changed, but what you were trying to figure out and what the code change represents as a decision. At the end of the day, read the log back. The experiment tests whether commit messages can double as a lightweight design diary and whether the practice changes how you think mid-task.

**3. The 15-minute prototype constraint**
Pick any UI idea — a widget, a flow, a micro-interaction — and build the whole thing in a single Claude Code session with a hard 15-minute wall. No second session, no cleanup pass. The constraint forces prioritization: what do you actually need to prove, and what's polish? Save the result as an experiment. The artifact is the constraint outcome, not the polished product.
