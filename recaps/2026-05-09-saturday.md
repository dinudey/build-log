### Ethics & Trust Analyzer

**What it was trying to learn**

Whether Claude can analyze visual and prototype artifacts — user flows, HTML prototypes, annotated screens — against AI UX ethics parameters in a way that is *actionable for UX designers specifically*, not researchers or compliance teams. The secondary question: can the output meaningfully distinguish between what a designer owns directly, what requires cross-functional collaboration, and what is outside design's scope entirely?

**What was actually built**

A self-contained interactive HTML prototype (~71KB) for a tool called the "Ethics & Trust Analyzer." Not a checklist — a multi-view design tool concept with four distinct interface layouts:

- **Report Document** — long-scroll audit format, printable, clinical but warm
- **Dashboard Grid** — card-based, KPI-first, scannable
- **Canvas Annotate** — spatial board with draggable sticky pins, FigJam-style
- **Split Inspector** — IDE-style with nav tree, findings table, and detail panel

The prototype analyzes a sample checkout flow with AI suggestions against five ethics pillars — Trust, Explainability, Transparency, Fairness, Accountability — surfacing 40 findings (8 HIGH, 18 MED, 14 LOW). Every finding carries a scope tag: **YOU CAN DO** (designer acts alone), **COLLABORATIVE · you lead** (needs ML Eng, Content, PM), or **OUT OF SCOPE · escalate** (legal, policy, support). In the sample: 55% yours, 33% collab, 12% out of scope.

An optional Socratic mode replaces prescriptive fixes with prompts — "What signal would help a user decide whether to accept, adjust, or reject this?" — positioning the designer as expert, the tool as facilitator.

The design system is intentional: warm paper background, Caveat (handwritten) for headings to maintain a sketch-quality feel, IBM Plex Mono for data codes, and a three-color scope palette (moss / ochre / clay) that lets a designer read ownership at a glance.

**Non-obvious decisions and tradeoffs**

The scope taxonomy is the central design bet. Most ethics review tools produce a flat list of issues. This one routes accountability — "here are 3 things you can address this week unilaterally, here are 2 things to bring to standup, here's what needs to go to legal." That shifts the tool's value from issue detection to ownership clarity.

The Socratic mode vs. prescriptive mode is an unresolved fork. Prescriptive is faster and more immediately useful; Socratic resists the idea that an AI should own the ethical judgment call. The prototype surfaces both but doesn't commit to a default — which is itself a decision worth revisiting.

Building this as rendered HTML rather than static screens means the prototype is simultaneously a design spec and a proof of concept for the output format. A designer who receives this file can open it in a browser today. The wireframe/working-tool boundary is deliberately blurred.

Exploring four dashboard views rather than one is a hypothesis machine: each view encodes an assumption about which kind of designer this tool is for.

**What it unlocked**

A concrete, opinionated answer to what AI UX ethics tooling for designers could look like as an actual product — one that could be handed off to engineering or published as an open-source tool. The scope taxonomy pattern (who owns this finding, not just what's wrong) is reusable beyond ethics — it applies to any design accountability context where ownership is ambiguous across functions.

The experiment also demonstrated that Claude Code can generate design-quality interactive prototypes quickly enough to explore multiple competing interface concepts in a single session — not just utility code.

**Loose ends**

- The experiment is marked "active" in its README but has had no commits since April 19. Worth deciding if it's paused or continuing elsewhere.
- The four view concepts exist as wireframes but have not been evaluated against real designer workflows. A follow-up session could pick one and develop it further, or wire up an actual Claude analysis pass behind it.
- An ADHD learning tool was initialized and immediately abandoned on April 18 — no artifacts remain. The prompt that started it may be worth revisiting.

**Artifact potential**

**HIGH — two angles:**

1. *The scope taxonomy as a design pattern.* "Who owns this?" is an underexplored dimension in AI UX ethics frameworks. The three-tier model (you / collab / out) is a practical, publishable concept other designers could apply without building a tool. Could become a standalone piece on designing accountability frameworks for cross-functional product teams.

2. *Case study: AI-native design prototyping.* The mechanics of going from a research question to a 71KB interactive prototype in one Claude Code session is worth documenting as an AI-native design practice. The specific move — using rendered HTML wireframes that double as functional artifacts — is a pattern worth naming.

## This week's nudge

Activity has been quiet since the ethics experiment launched in April. Three experiments worth trying in the next session — each completable in 1–2 hours:

**1. Run the analyzer against itself**
Feed the Ethics & Trust Analyzer wireframes back into Claude and ask it to produce the assessment output the tool is designed to display. Does Claude identify the same five pillars? Does it spontaneously generate scope tags? How close is the raw AI output to what the wireframes assume the output should look like? This closes the loop on the experiment's original question and either validates or reshapes the prototype's core premise.

**2. Extract the scope-of-influence pattern as a reusable component**
Strip the three-tier scope model (you / collab / out) out of the ethics context and apply it to a different design challenge — a design system contribution process, a product spec handoff, a research debrief. Build one standalone HTML component that takes a finding and a scope tag and renders the right color, label, and action block. Tests whether the pattern generalizes or was specific to ethics framing.

**3. Claude Code as a general design reviewer**
Pick any real design artifact — a product screenshot, a Figma export, a landing page — and write a Claude Code prompt that produces a structured design review with no ethics framing. What format does the output naturally take? How does it compare to a manual crit from a senior designer? This tests whether the ethics scaffold in the current experiment is load-bearing or whether Claude's design analysis generalizes across review types.
