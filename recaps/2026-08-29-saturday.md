### AI UX Ethics Analyzer

**What the experiment was trying to learn**

Whether Claude can analyze visual and prototype artifacts — wireframes, flows, HTML prototypes — and assess them against AI UX ethics dimensions (Trust, Explainability, Transparency, Fairness, Accountability) in a way that is genuinely useful to a *UX designer*, not a researcher or ML engineer. The harder secondary question: can the output distinguish what is the designer's to fix vs. what requires cross-functional collaboration vs. what is outside design's scope entirely?

**What was actually built**

A set of wireframe concepts in HTML (~71KB) exploring the dashboard UI for an AI ethics analysis tool, built in Claude Code Design. The screens explore how ethics feedback would surface in a design review interface — per-dimension scoring, finding types, and some way to triage results by who owns the fix. Multiple design options were generated, suggesting the output format itself remains an open question.

**Key decisions or tradeoffs**

The framing sharpens the experiment considerably. Most AI ethics evaluation work targets ML practitioners — it assesses models, not interfaces. Translating that to a designer-facing tool requires a second layer of interpretation: not just "this UI has a trust problem" but "here is what you can change in Figma today." The scope-of-control axis (designer-owned vs. cross-functional vs. model-level) is what makes this genuinely hard and interesting, rather than just a checklist exercise.

Using Claude Code Design as the prototyping environment is itself an AI-native practice choice — it collapses analysis and design exploration into a single session rather than separating research from wireframing.

**What it unlocked**

Proof that wireframe-level exploration of this concept is viable and generative. The multiple options produced suggest the analysis output format isn't settled — there's a real design question about whether ethics feedback should surface as a scorecard, an annotation layer, a prioritized checklist, or something else. Each format implies a different workflow integration point for the designer.

**Loose ends**

The experiment is marked active but has had no commits since April 2026 (~4 months). The wireframes exist as a UI concept. What hasn't happened yet: running actual Claude-driven ethics analysis on a real UI artifact and testing whether the output format holds up. The concept is ahead of the implementation.

## This week's nudge

No experiments ran this week. Three specific ideas worth trying in the next 1–2 hours each:

**1. Run the ethics analysis itself — close the loop on the existing experiment**

Take a real AI product UI (ChatGPT, Gemini, Copilot, or any AI-powered feature you use regularly) and give Claude the URL or screenshots. Ask it to evaluate the interface against the five dimensions: Trust, Explainability, Transparency, Fairness, Accountability. Then ask it to sort findings by "what the UX designer can change today / what needs cross-functional discussion / what is model-level and outside design's scope." The output format that comes back *is* the experiment — document it, screenshot it, note what's missing. This closes the loop on the April wireframes in one session.

**2. Build a Claude Code post-session design rationale routine**

After any Claude Code session where you make UI or product decisions, run a prompt that asks Claude to reconstruct the decisions made and why — a post-session design rationale log. The prompt would ask: what options were considered, what was chosen, what tradeoff was accepted. Set this up as a short Claude Code hook or alias that outputs a structured markdown file. Takes about an hour to set up, generates value immediately, and is itself an example of AI-native documentation practice.

**3. Prototype the scope-of-control taxonomy**

The secondary question in the ethics analyzer experiment — who owns the fix — is actually a taxonomy design problem. Spend an hour building a minimal version: 15–20 common AI UX ethics issues (e.g., "model output isn't explained to the user," "error states are opaque," "confidence is presented as certainty") each mapped to its owner tier (designer / PM+designer / engineering / model team). This becomes the schema that determines what the ethics analyzer can and can't output, and it can be validated quickly by sharing with one designer or PM.
